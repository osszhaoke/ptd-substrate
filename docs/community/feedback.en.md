# Trial feedback

Use a public issue for a problem with normal use. If someone may be able to read another person's data or credentials or bypass an access check, use the [private vulnerability report](https://github.com/osszhaoke/ptd-substrate/security/advisories/new). [Chinese version](feedback.md)

## Reproduce and describe the problem

1. Try the bundled sample in a new fictional space. Note the [trial task](trial-tasks.en.md) number, the interface language and the page where the problem appears.
2. You can copy the fields from the [template included here](../../.github/ISSUE_TEMPLATE/trial_feedback.md). Once the template is on the default branch, open the [trial feedback form](https://github.com/osszhaoke/ptd-substrate/issues/new?template=trial_feedback.md) to submit a public issue. Give the release version, Mac model and chip, macOS version and Python version. List the shortest steps someone else can follow.
3. Describe what you expected in one sentence. Then describe what happened or quote the short error message. For example, “Task 3, copy with two times. I expected 08:00 and 08:01 but the review page showed one row.” If it happens occasionally, give the number of attempts and how often it happened.

## Before sharing a screenshot

Prefer a single view of the fictional space. Crop out other windows, private address parameters and notifications. Cover names, personal paths, space identifiers, account details and health or genetic information with solid blocks. Export the edited image and reopen it to check the result before attaching it. Keep databases, settings files, credentials, real reports and raw health data out of the report. See the [security policy](../../SECURITY.en.md) for security reports.

## After you submit

Maintainers will do their best to reply. There is no fixed response time. Add new steps to the original issue or say if the problem has stopped. If you later find a possible security issue, send further details through the private channel.
